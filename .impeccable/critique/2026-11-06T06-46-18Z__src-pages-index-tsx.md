**五个优先问题**

1. **[P1] 手机导航发生挤压与重叠。** 390px 下“知识库”竖排，搜索与 GitHub 几乎占用同一矩形区域。根因是 custom.css:267 的全局 display:inline-flex 覆盖移动导航隐藏规则。它影响查找入口和网站可信度。修复时恢复移动断点，顶部保留菜单、Logo、独立搜索入口，次级链接进入已有抽屉；控件提供至少 44px 的易触达区域。适用：$impeccable adapt。

2. **[P1] 所有内容同级展开，回访与手机查找成本高。** 手机整页约 5195px，工具规范到约 y=3906 才出现；6 个面试主题、8 篇小册、5 项工具都要求读者逐项比较。相关位置：index.tsx:315、index.module.css:156。改为先选用途“准备面试 / 练手写题 / 查工程方案”，提供分区直达；手机主题采用标题加一句摘要的紧凑目录，例题按需展开。适用：$impeccable layout、$impeccable distill。

3. **[P2] 首屏强调设计机制，内容价值与作者判断不突出。** 1440px 下标题第二行只剩一个“档”，右侧大片空白；第一张内容卡约到 y=570 才出现。相关位置：index.tsx:295、index.module.css:30。重新设计应以“能读到什么、解决什么问题”为标题依据，缩短开场，用一篇真实精选文章承接首屏；处理中文断行。适用：$impeccable clarify、$impeccable typeset。

4. **[P2] 关键阅读线索过小、过淡。** 代表题仅 12.5px，“查看全部”11px；浅色辅助文字 #767e86 在白底为 4.12:1、浅灰底约 3.74:1，低于此次检测采用的小字 4.5:1 阈值。相关位置：custom.css:30、index.module.css:238 和 :258。将决定“读什么”的摘要与例题提升到 14–15px，并采用更深的次级正文色；小号索书号降为元信息。暗色正文较稳，但导航搜索快捷键仍有约 4.29:1 的不足。适用：$impeccable typeset、$impeccable polish。

5. **[P2] 链接文案和到达位置不完全一致。** 单篇小册都写“查看全部”；点某道例题只进入章节顶部；全局“知识库”实际进入手写题分类。相关位置：index.tsx:225、docusaurus.config.ts:105。小册改为“阅读小册”，例题若是快捷入口就用已核实的正文锚点，“知识库”应指向总目录。适用：$impeccable clarify。

**认知负荷与读者体验**

8 项检查中，单一焦点、相关内容分组、基础视觉层级、一次一个决定、减少记忆负担通过；信息分块、同级选项数量、渐进呈现未通过，共 3 项失败，属中等负荷。6/8/5 个选项不意味着必须删内容，而意味着需要更清楚的分组、导读或按需展开。

首次访客能看懂技术名，但难以判断“JavaScript 基础”和“核心进阶”先看哪篇；手机读者先遇到导航拥挤，再面对长列表；低视力读者则受淡小字影响。键盘用户的跳过内容和可见焦点表现良好，本次未观察到焦点陷阱。

情绪路径是“安静可信 → 例题建立信任 → 重复卡片使重点变平 → 随记与页脚结束”。新的首页需要在首屏给出阅读理由，在中段突出精选，在末尾给出明确的继续阅读入口。

**建议的重新设计方向：有作者判断的前端知识刊**

以作者导读、一个阅读重点和紧凑目录建立新首页。保留站点名称、Logo、真实文章、现有路由和搜索能力，主题色作为内容标签使用。构图由一个重点与若干轻量索引构成，降低重复边框卡片的占比。

| 首屏 | 苏木身份、笔记价值、搜索、精选入口 | 简洁开场，桌面配一篇真实精选，手机优先显示搜索与阅读入口 |
| 选读路径 | 准备面试 / 练手写题 / 查工程方案 | 3 个用途清楚的入口，直达对应内容 |

| 主题索引 | JS、Vue、React、工程化、Node、小程序 | 桌面明确分组，手机紧凑目录行 |
