在前端工程化及大厂面试中，掌握经典设计模式是解耦复杂业务、优化架构设计和提升代码可维护性的关键。以下是前端开发中最常用的 9 种设计模式的深度解析与实战场景：



### 一、 外观模式 (Facade Pattern)

#### 1. 核心定义

外观模式为子系统中的一组接口提供一个统一的高层接口，使子系统更容易使用。它将多个子系统中的复杂逻辑进行抽象，从而提供一个更统一、更简洁、更易用的 API。



#### 2. 代码实现示例

以兼容不同浏览器的事件绑定及参数封装为例：



JavaScript

```
// 统一的事件绑定外观函数
let addMyEvent = function (el, ev, fn) {
  if (el.addEventListener) {
    el.addEventListener(ev, fn, false);
  } else if (el.attachEvent) {
    el.attachEvent('on' + ev, fn);
  } else {
    el['on' + ev] = fn;
  }
};

// 封装接口
let myEvent = {
  stop: e => {
    e.stopPropagation();
    e.preventDefault();
  }
};
```

#### 3. 应用场景与优缺点

- **应用场景**：
  - 开发初期，在数据访问层与业务逻辑层、业务逻辑层和表示层之间建立外观 (`Facade`) 分离层次。
  - 维护遗留大型系统时，为设计粗糙和高度复杂的代码提供清晰的接口，让新系统和 `Facade` 交互。
- **优点**：减少系统相互依赖，提高灵活性与安全性。
- **缺点**：不符合开闭原则，如果要修改逻辑或继承重写会相对麻烦。

### 二、 代理模式 (Proxy Pattern)

#### 1. 核心定义

为一个对象提供一个代用品或占位符，以便控制对它的访问。代理对象在客户端和目标对象之间起到中介作用，常用于保护目标对象或扩展目标对象的功能。



#### 2. 代码实现示例

以事件代理（Event Delegation）为例：



JavaScript

```
let ul = document.querySelector('ul');
ul.addEventListener('click', event => {
  // 利用冒泡机制，通过父元素代理子元素的点击事件
  console.log(event.target);
});
```

#### 3. 应用场景与优缺点

- **应用场景**：HTML 元素事件代理、图片懒加载代理、Vue3 的 `Proxy` 响应式拦截。
- **优点**：降低系统耦合度，符合开闭原则，且能起到保护和扩展目标对象的作用。
- **缺点**：由于存在非直接访问的中间层，处理请求速度可能会有细微的性能开销。

### 三、 工厂模式 (Factory Pattern)

#### 1. 核心定义

定义一个用于创建对象的接口，由子类决定实例化哪一个类。该模式使一个类的实例化延迟到了子类，构造函数与创建者分离。



#### 2. 应用场景与优缺点

- **应用场景**：
  - 当不想让某个子系统与较大的对象形成强耦合，希望在运行时从许多子系统中进行挑选时。
  - 将 `new` 操作简单封装，遇到复杂对象创建需求时。
- **优点**：调用者只需知道产品名称即可创建，构造函数与创建者分离，符合开闭原则，扩展性高。
- **缺点**：引入抽象层，在一定程度上增加了系统的抽象性和代码理解难度。

### 四、 单例模式 (Singleton Pattern)

#### 1. 核心定义

保证一个类仅有一个实例，并提供一个全局访问点。通过隐藏构造函数并暴露 `getInstance()` 方法来控制实例化的过程。



#### 2. 代码实现示例

JavaScript

```
const Singleton = (function () {
  let instance;
  function init() {
    return {
      name: 'SingleInstance',
      time: Date.now()
    };
  }
  return {
    getInstance: function () {
      if (!instance) {
        instance = init();
      }
      return instance;
    }
  };
})();

const s1 = Singleton.getInstance();
const s2 = Singleton.getInstance();
console.log(s1 === s2); // true
```

#### 3. 应用场景与优缺点

- **应用场景**：全局状态管理（如 `Vuex` 和 `Redux` 中的 Store）、全局登录框、弹窗组件。
- **优点**：划分命名空间，减少全局变量，节省系统资源，便于维护。
- **缺点**：引入了全局状态，可能导致模块间强耦合，不利于单元测试。

### 五、 策略模式 (Strategy Pattern)

#### 1. 核心定义

定义一系列的算法，把它们一个个封装起来，并且使它们可以互相替换。



#### 2. 应用场景与优缺点

- **应用场景**：复杂的表单验证规则（将不同的校验逻辑拆分为独立的策略对象），可有效避免庞大的 `if-else` 或 `switch-case` 语句。
- **优点**：完美支持开放-封闭原则，使得算法易于切换、理解和扩展。
- **缺点**：会在程序中增加许多策略类或策略对象，开发者必须了解各个策略之间的差异。

### 六、 迭代器模式 (Iterator Pattern)

#### 1. 核心定义

提供一种方法顺序访问一个聚合对象中的各个元素，而又不暴露该对象的内部表示。



#### 2. 应用场景与优缺点

- **应用场景**：ES6 中的 `Iterator` 迭代器协议以及 `for...of` 循环。
- **核心价值**：提供一致的遍历各种数据结构的方式，无需了解数据的内部结构。

### 七、 观察者模式 / 发布-订阅模式 (Observer / Pub-Sub Pattern)

#### 1. 核心定义

被观察对象（Subject）维护一组观察者（Observer），当被观察对象状态改变时，通过调用观察者的某个方法将变化自动通知到所有观察者。



#### 2. 代码实现示例

JavaScript

```
class Subject {
  constructor() {
    this.observers = [];
  }
  subscribe(observer) {
    this.observers.push(observer);
  }
  unsubscribe(observer) {
    this.observers = this.observers.filter(obs => obs !== observer);
  }
  fire(data) {
    this.observers.forEach(observer => observer.update(data));
  }
}
```

#### 3. 应用场景与优缺点

- **应用场景**：DOM 事件监听、Vue 的响应式数据劫持与通知机制。
- **优点**：实现松耦合的广播通信，目标对象与观察者之间建立抽象耦合，扩展性强。
- **缺点**：过度使用会导致对象间关系弱化，程序难以追踪和维护。

### 八、 中介者模式 (Mediator Pattern)

#### 1. 核心定义

通过一个中介者对象包装一系列对象相互作用的方式，使对象不必直接相互作用，而是由中介者协调交互，从而实现松散耦合。



#### 2. 应用场景与优缺点

- **应用场景**：购物车中商品选择、颜色选择、购买数量等多表单联动交互。
- **优点**：将网状多对多关系转化为一对多关系，使各对象耦合松散。
- **缺点**：中介者对象自身往往非常庞大且复杂，本身较难维护。

### 九、 访问者模式 (Visitor Pattern)

#### 1. 核心定义

将算法与对象结构分离的设计模式。它允许在不改变一个对象结构的前提下，为该对象增加新的操作和逻辑。



#### 2. 应用场景与优缺点

- **应用场景**：对象结构中的类很少改变，但经常需要在此对象结构上定义新的操作，常用于扩展复杂的第三方库和工具。
- **优点**：符合单一职责原则，具有极佳的扩展性。
- **缺点**：具体元素对访问者公布细节，在一定程度上违反了迪米特原则与依赖倒置原则。
